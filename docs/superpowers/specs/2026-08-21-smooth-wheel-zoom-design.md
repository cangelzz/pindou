# 平滑滚轮缩放设计

## 背景

GitHub issue [#5](https://github.com/cangelzz/pindouverse/issues/5) 请求在编辑器画布中使用鼠标滚轮放大和缩小。现有工具栏每次按 `1.25` 倍调整缩放，适合按钮操作，但用于滚轮时跳跃幅度过大。

本功能为主编辑器增加实时、连续、以鼠标指针为中心的滚轮缩放。Desktop、Chrome/Edge 扩展和 VS Code 扩展共用 `PixelCanvas`，因此共享实现一次即可覆盖这些平台。独立 H5 查看器不在本次范围内。

## 目标

- 在主画布内使用普通滚轮直接缩放。
- 同时支持 `Ctrl/Cmd + 滚轮`，并阻止浏览器页面级缩放。
- 标准鼠标滚轮一格约缩放 `10%`。
- 高精度触控板根据细粒度输入连续缩放。
- 每个 `wheel` 事件立即生效，不添加缓动、惯性或档位累积。
- 缩放始终以鼠标指针为中心。
- 保留现有 `0.5～40` 缩放范围。
- 保持工具栏现有 `1.25` 倍按钮行为不变。

## 非目标

- 不为缩放添加动画或惯性。
- 不改变工具栏按钮的缩放步长。
- 不增加移动端双指缩放。
- 不修改独立 H5 `BeadCanvas`。
- 不全局接管 `window` 或 `document` 上的滚轮事件。

## 交互设计

### 输入范围

仅在 `PixelCanvas` 的画布容器内监听 `wheel`：

- `deltaY < 0`：放大。
- `deltaY > 0`：缩小。
- `deltaY === 0`：不改变状态。
- 普通滚轮和带 `Ctrl` 或 `Meta` 修饰键的滚轮使用同一缩放路径。

处理过的事件必须调用 `preventDefault()`，避免页面滚动以及浏览器、扩展标签页或 VS Code webview 的页面级缩放。监听不得挂到全局，避免影响变化比较窗口和图纸导入窗口的既有滚轮行为。

### 缩放手感

滚轮输入采用指数映射，不使用工具栏的固定 `1.25` 倍档位，也不直接线性加减 `zoom`。

先根据 `WheelEvent.deltaMode` 将 `deltaY` 归一化为像素尺度：

- `DOM_DELTA_PIXEL`：直接使用。
- `DOM_DELTA_LINE`：乘以固定行高常量。
- `DOM_DELTA_PAGE`：乘以当前画布容器高度。

归一化值随后限制到合理的单事件范围，防止特殊鼠标驱动、远程桌面或窗口切换产生的异常大输入。目标倍率使用指数函数计算：

```text
factor = exp(-normalizedDeltaY * sensitivity)
nextZoom = clamp(currentZoom * factor, 0.5, 40)
```

`sensitivity` 应校准为标准鼠标滚轮一格约产生 `1.10×` 或 `÷1.10` 的变化。触控板较小的 `deltaY` 自然产生更细小的倍率，因此无需阈值、计时器或动画。

## 指针锚定

缩放前先计算鼠标指针相对画布容器的位置，并将其转换为画布逻辑坐标：

```text
canvasX = (mouseX - oldOffsetX) / oldCellSize
canvasY = (mouseY - oldOffsetY) / oldCellSize
```

计算新缩放和新格子尺寸后，更新偏移：

```text
newOffsetX = mouseX - canvasX * newCellSize
newOffsetY = mouseY - canvasY * newCellSize
```

这样鼠标指针下的珠子在缩放前后保持原位。若缩放已处于 `0.5` 或 `40` 边界，继续向边界外滚动不得改变缩放或偏移。

## 连续渲染精度

现有 `setZoom` 将 `cellSize` 设置为 `Math.round(16 * zoom)`。这会使细粒度滚轮输入在跨过整数像素前没有视觉变化，与连续缩放目标冲突。

本功能将 `cellSize` 保持为浮点值：

```text
cellSize = 16 * zoom
```

以下路径必须统一使用同一个浮点 `cellSize`：

- Canvas 尺寸与绘制坐标；
- 珠子和网格位置；
- 鼠标坐标换算；
- 命中检测；
- 平移与选择交互；
- 适应窗口及 1:1 操作。

工具栏显示的百分比可以继续四舍五入，但内部状态和绘制尺寸不得量化。非整数坐标上的网格线可能出现正常抗锯齿；不得为了整数锐利度牺牲连续缩放。

## 组件与职责

### 纯缩放计算

将以下逻辑放入可独立测试的纯函数或小型工具模块：

- `deltaMode` 归一化；
- 单事件输入限制；
- 指数倍率计算；
- 缩放上下限；
- 指针锚定后的偏移计算。

该单元不读取 DOM 或 store，只接收当前视图状态、滚轮输入和指针位置，返回下一组 `zoom`、`cellSize`、`offsetX`、`offsetY`。当输入不应导致变化时返回原状态。

### `PixelCanvas`

`PixelCanvas` 负责：

- 从 wheel 事件取得容器内指针位置和容器高度；
- 调用纯计算逻辑；
- 在结果变化时更新 editor store；
- 阻止已处理事件的默认行为。

### Editor store

store 继续作为 `zoom`、`cellSize` 和偏移的状态来源。`setZoom` 必须保留浮点 `cellSize`，并继续保证缩放不影响项目 dirty 状态。

工具栏、适应窗口和其他缩放入口仍通过 store 更新视图，不改变它们现有的交互步长。

## 错误与边界处理

- 非有限 `deltaY`、缩放值、格子尺寸或坐标不得写入 store。
- `oldCellSize <= 0` 时不得执行锚点换算。
- `deltaY === 0` 时不更新 store。
- 计算后的 zoom 必须限制在 `0.5～40`。
- 当 clamp 后的 zoom 与当前 zoom 相同时，偏移保持不变。
- 单次归一化输入必须限制上限，避免异常跳变。
- 事件处理只修改视图状态，不创建历史记录，也不将项目标记为 dirty。

## 测试设计

### 单元测试

为纯缩放计算和 store 精度添加测试：

1. `deltaY < 0` 放大，`deltaY > 0` 缩小。
2. 标准滚轮一格约变化 `10%`。
3. 小幅 `deltaY` 产生小幅、非量化变化。
4. `DOM_DELTA_PIXEL`、`LINE`、`PAGE` 被合理归一化。
5. 单次超大输入被限制。
6. 指针下的画布逻辑坐标在缩放前后保持不变。
7. 视口中心和边缘位置都能正确锚定。
8. zoom 不低于 `0.5`、不高于 `40`。
9. 到达边界后继续滚动不改变偏移。
10. `deltaY === 0` 和非有限输入不改变状态。
11. `setZoom` 保留浮点 `cellSize`。
12. 缩放不改变项目 dirty 状态。

### VS Code Playwright

在共享 webview bundle 上验证真实 DOM 行为：

1. 普通滚轮可以连续放大和缩小。
2. `Ctrl/Cmd + 滚轮`同样有效。
3. 小幅连续事件每次立即改变视觉尺寸，不等待动画或定时器。
4. 变化幅度明显小于工具栏单次 `25%` 跳变。
5. 指针锚点在缩放前后保持稳定。
6. 画布外滚轮不改变 editor zoom。
7. wheel 缩放不会改变 dirty 状态。
8. 工具栏放大、缩小、1:1 和适应窗口继续工作。

### 回归测试

确认以下交互在浮点 `cellSize` 下保持一致：

- 绘制与擦除命中；
- 平移；
- 选择区域；
- 变化比较窗口自身的滚轮缩放；
- 图纸导入窗口的滚动及 `Ctrl/Cmd + 滚轮`行为。

浏览器扩展可增加一条烟雾测试，确认共享实现生效且不会触发页面级缩放；无需在每个平台重复完整行为矩阵。

## 验收标准

- 在主画布上滚时实时平滑放大，下滚时实时平滑缩小。
- 标准鼠标滚轮一格约变化 `10%`，不出现工具栏式 `25%` 跳变。
- 触控板细粒度输入产生可见的连续变化。
- 普通滚轮和 `Ctrl/Cmd + 滚轮`均可用。
- 鼠标指针下的珠子在缩放过程中保持原位。
- 浏览器页面、扩展标签页和 VS Code webview 不发生页面级缩放。
- 缩放始终位于 `0.5～40`，边界处无偏移漂移。
- 工具栏缩放、绘制、选择、平移、比较窗口和导入窗口无行为回归。
- 滚轮缩放不将项目标记为 dirty。
