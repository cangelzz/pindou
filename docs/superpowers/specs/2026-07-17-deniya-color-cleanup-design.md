# Deniya 拼豆配色规整设计

## 目标

以 `samples/deniya1.pindou` 为当前人工修改基线，以
`temp/deniya_orig.png` 为色彩参考，生成三档可比较的配色规整方案。重点减少无意义的
低频近似色、孤立噪点和杂乱衔接，同时保留五官与饰品中数量少但有表达作用的颜色。

本轮不直接覆盖基线文件。最终由用户从候选方案中选择，确认后才更新正式 sample。

## 输入与约束

- 拼豆基线：`samples/deniya1.pindou`，尺寸 101×89，v3 扁平 cell 格式。
- 原图参考：`temp/deniya_orig.png`。
- 当前基线已经包含人工修改，算法必须从基线出发，不能重新全图匹配原图。
- 保持画布尺寸、透明区域、网格配置和项目元数据不变。
- 每个候选的 `canvasData` 与 `layers[0].data` 必须完全一致。
- 颜色索引必须落在 MARD 221 色板的有效范围内。

## 处理路线

采用混合式规整，而不是仅按使用量删除颜色。

### 1. 原图参考采样

将原图按 101×89 网格映射。每格从中心区域采样中位色，避开原图网格线。参考色只用于
判断一次替换是否恶化视觉保真度，不用于重建整张拼豆稿。

### 2. 保护区域

显式保护以下语义区域：

- 双眼及眼线；
- 嘴部；
- 发饰宝石；
- 蓝色蝴蝶结；
- 项圈与吊坠；
- 金属链。

保护区通过 101×89 网格坐标中的矩形或多边形配置表达。三个候选都不得修改保护区内
的任何 cell；保护区只参与邻域判断，不参与颜色归并或空间规整。

此外自动保护：

- 与邻居存在高对比的轮廓 cell；
- 面积虽小，但内部包含稳定高对比结构的连通区域；
- 透明区域边界。

### 3. 分区颜色归并

将主体粗分为头发、皮肤、服装和背景/透明区域。低频色只允许向同一分区内的候选颜色
归并，避免粉色头发、肤色和蓝色服装互相吞色。

候选替换同时考虑：

- MARD 色板上的感知色差；
- 替换前后相对原图参考色的误差变化；
- 候选颜色在局部邻域和所属分区中的使用量；
- 替换后是否减少短碎线、孔洞或锯齿式跳色。

只有色相相容且原图误差没有超过该档方案阈值时才允许替换。全局使用量低不是单独的
删除理由。

### 4. 空间规整

在颜色归并后处理孤立 cell、小连通块和不连续边缘：

- 孤立点只有在邻域存在明确主色时才替换；
- 小连通块优先并入边界接触最多、且色差合理的邻色；
- 发丝和衣纹允许保留窄线，但消除一格一色交替形成的杂乱跳色；
- 高对比轮廓不能被平滑穿透；
- 每轮使用上一轮的快照批量决策，避免扫描顺序影响结果。

## 三档候选

### Light

重点清除孤立噪点和极小低频色块。颜色总数只作自然下降，不设强制目标。适合最大限度
保留现稿。

### Balanced

在 Light 基础上合并同分区内的近似低频色，并整理发丝、皮肤和服装的色块衔接。这是
默认推荐方案。

### Compact

使用更宽松的色差和连通块阈值，进一步压缩近似颜色，但沿用相同保护区和轮廓保护。
不得为了达到固定色数强行替换。

## 输出

候选产物写入 `temp/deniya-cleanup/`，不覆盖正式 sample：

- `deniya1-light.pindou`
- `deniya1-balanced.pindou`
- `deniya1-compact.pindou`
- 每档对应的无网格像素渲染 PNG；
- 每档对应的图纸预览 PNG；
- 每档相对基线的修改热区图；
- 汇总 JSON，包含颜色数、替换 cell 数、低频色数量、小连通块数量和原图色差变化。

浏览器视觉伴侣展示基线、三档候选和重点局部裁剪。展示前由执行者按以下标准先筛选，
并标注推荐的两档：

1. 噪点和无意义低频色明显减少；
2. 发丝、肤色和服装衔接更连续；
3. 五官与饰品细节无损；
4. 轮廓没有变软或断裂；
5. 相对原图的感知色差没有不合理上升。

## 实现边界

- 新增一个独立的候选生成与渲染脚本，不改变编辑器运行时行为。
- 不直接复用当前 `scripts/simplify-colors.mjs`：该脚本按旧版对象 cell 读取数据，且没有
  语义保护、原图误差约束或分区规则。
- 不在本轮自动选择并覆盖 `samples/deniya1.pindou`。
- 不修改用户现有的海报脚本改动。

## 验证

每个候选必须通过：

- JSON 可解析且版本为 3；
- 画布与每层行列数均为 101×89；
- `canvasData` 与可见层合成结果完全一致；
- 所有非空颜色索引有效；
- 透明 cell 数量不发生非预期变化；
- 保护区逐 cell 对比，必须与基线完全一致；
- 同一输入重复执行得到字节一致的候选；
- 项目现有测试全部通过。

人工验收通过浏览器并排预览完成，最终 sample 的选择与覆盖由用户明确确认。
